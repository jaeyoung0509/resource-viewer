PRD: K8s 기반 분산 리소스 모니터링 시스템 (Web-htop)1. 프로젝트 개요프로젝트명: K8s-Web-Htop (가칭)목표: Kubernetes 클러스터 내 모든 노드의 리소스(CPU, Memory, Disk) 사용량을 실시간으로 수집하여 웹 대시보드에서 시각화한다.학습 목표:OS: 리눅스 /proc 파일 시스템 구조 이해, 컨테이너 격리 및 네임스페이스 탈출(Volume Mount).Network: WebSocket 프레임 처리, Redis Pub/Sub 패턴, K8s Service Discovery(DNS).Infra: Kubernetes DaemonSet 패턴 및 멀티 노드 아키텍처 이해.2. 시스템 아키텍처Node Agent (DaemonSet): 각 노드(K3d 컨테이너)에 하나씩 뜨는 Go 프로그램. 호스트의 /proc을 읽어 Redis로 쏨.Message Broker (Redis): 데이터 중계소. Pub/Sub 기능 제공.Hub Server (Deployment): Redis를 구독하다가, 웹 클라이언트(브라우저)가 붙으면 WebSocket으로 데이터 푸시.Frontend: HTML + Vanilla JS (또는 Chart.js)로 실시간 그래프 렌더링.3. 필요 개발 도구 및 환경 (Local Setup)이 프로젝트를 로컬에서 진행하기 위해 설치해야 할 필수 도구들입니다.A. 필수 소프트웨어Docker (Desktop or Engine)용도: K3d가 도커 컨테이너 위에서 K8s 노드를 만들기 때문에 필수입니다.Go (1.20 이상)용도: Agent와 Hub Server 개발 언어.Kubectl용도: K8s 클러스터 제어 및 배포 명령 도구.K3d (K3s in Docker)용도: 로컬에서 멀티 노드 K8s 클러스터를 띄워주는 도구. (Minikube보다 멀티 노드 구성이 훨씬 가볍고 빠름)Wscat (npm install -g wscat)용도: 브라우저 UI 만들기 전, 터미널에서 WebSocket 데이터가 잘 오는지 디버깅할 때 필수.B. K3d 클러스터 구성 전략 (중요)단일 노드가 아닌, 1 Master + 2 Worker 구조로 만들어야 "분산 모니터링"의 의미가 있습니다.# 터미널에서 실행할 명령어 (프로젝트 시작 시)
k3d cluster create my-monitor \
  --servers 1 \
  --agents 2 \
  -p "8080:30000@loadbalancer"
--agents 2: 워커 노드 2개를 생성 (내 컴퓨터에 도커 컨테이너가 총 3개+로드밸런서 1개 뜸).-p: 로컬의 8080 포트를 K8s 내부 서비스로 포워딩 (웹 대시보드 접속용).4. 상세 기능 요구사항A. Monitoring Agent (Go App 1)배포 형태: Kubernetes DaemonSet핵심 로직:OS 시그널 처리: 프로그램 종료 시 우아하게(Graceful) 종료.데이터 수집: gopsutil 라이브러리를 사용하되, 환경변수 HOST_PROC를 통해 경로를 동적으로 받도록 구현.Why? 로컬 개발 땐 /proc, K8s 배포 땐 /host/proc을 읽어야 함.데이터 전송: 수집된 데이터를 JSON으로 직렬화하여 Redis에 PUBLISH (채널명: metrics:node-name).식별자: 자신의 노드 이름(Hostname)을 알아야 함 (os.Hostname() 사용).B. Redis (Infra)배포 형태: Kubernetes StatefulSet 또는 단순 Deployment설정: 별도 비밀번호 없이 기본 설정 사용 (학습용).Service: 클러스터 내부에서 redis-service:6379로 접근 가능해야 함.C. Hub Server (Go App 2)배포 형태: Kubernetes Deployment (Replicas: 1)핵심 로직:Redis 연결: SUBSCRIBE metrics:* 패턴으로 모든 노드의 데이터를 구독.WebSocket 관리: gorilla/websocket 사용. /ws 엔드포인트 개방.브로드캐스팅: Redis에서 메시지가 오면, 현재 연결된 모든 WebSocket 클라이언트에게 WriteJSON.D. Frontend (Dashboard)형태: Hub Server가 서빙하는 정적 HTML 파일 (index.html).기능:ws://localhost:8080/ws 연결.메시지를 받으면 노드 이름별로 구분하여 화면에 수치 표시.(선택) Chart.js 등을 이용해 실시간 꺾은선 그래프 그리기.5. 단계별 구현 로드맵Phase 1: 로컬 개발 (Non-K8s)목표: Docker 없이 내 PC에서 프로세스 3개 띄워서 통신 확인.Action:로컬에 Redis 설치 및 실행 (docker run -p 6379:6379 redis).Agent 개발: 내 PC의 CPU 정보 읽어서 Redis에 쏘는 코드 작성.Hub 개발: Redis 읽어서 콘솔에 찍는 코드 작성.검증: redis-cli monitor로 데이터 흐름 확인.Phase 2: 컨테이너화 (Dockerizing)목표: Go 앱들을 Docker Image로 빌드.Action:Dockerfile 작성 (Multi-stage build 추천).docker build -t my-agent:v1 .docker build -t my-hub:v1 .Phase 3: K3d 배포 (Kubernetes)목표: 실제 K3d 클러스터에 배포하고 /proc 마운트 성공하기.Action:K3d 클러스터 생성.이미지 로드: k3d image import my-agent:v1 -c my-monitor (로컬 이미지를 K3d로 넣기).DaemonSet YAML 작성 (가장 중요): hostPath 볼륨을 사용하여 호스트의 /proc을 컨테이너의 /host/proc에 마운트.배포 및 로그 확인: kubectl logs -f daemonset/agent.6. 예상되는 기술적 난관 (Troubleshooting)Q: Agent가 리소스를 제대로 못 읽어요.A: 컨테이너 내부의 /proc을 읽으면 안 됩니다. YAML에서 마운트한 /host/proc 경로를 Go 코드에서 읽고 있는지 확인하세요. gopsutil 사용 시 common.SetHostProc("/host/proc") 같은 설정이 필요할 수 있습니다.Q: Hub Server가 Redis를 못 찾아요.A: K8s Service 이름(redis-service)이 올바른지, 포트가 맞는지 확인하세요. 같은 Namespace에 있어야 DNS가 바로 풀립니다.
